# Repository guidance

This file provides guidance to contributors and coding agents working in this repository.

## Project Overview

Open-data repository by Digital4Better providing geographic and environmental data for calculating digital service footprints. Used by fruggr (www.fruggr.io). Published as `@digital4better/data` on npm.

## Commands

- **Install dependencies**: `yarn --frozen-lockfile`
- **Generate all data + build site**: `yarn build`
- **Generate data only**: `yarn build:data` (runs `ts-node .` which executes `index.ts`)
- **Dev server (site)**: `yarn start` (Vite, serves the `site/` directory)
- **Build site only**: `yarn build:site`
- **Version bump**: `npm version patch` (auto-updates `releaseDate` in package.json via the `version` hook)

Keep that update on the `version` hook: npm rewrites package.json after `preversion` runs, discarding anything that hook wrote.

There is no `engines` field on purpose: the published package contains data files only, so build-time requirements must not leak to consumers.

## Architecture

### Data Generation Pipeline (`index.ts`)

Single entry point that fetches external data, computes metrics, and exports CSV+JSON files into `data/`. The pipeline runs sequentially:

1. **`generateClouds()`** — reads cloud provider JSON from `data/cloud/` and exports CSV equivalents
2. **`generateCountries()`** — computes geographic distances (country-to-country, region-to-region, user-to-datacenter) from `data/country/regions.json`
3. **`generateFactors()`** — the main pipeline:
   - Fetches global energy mix data from Ember (monthly + yearly wide generation CSVs at `files.ember-energy.org`; legacy long-format URLs return a migration notice)
   - Fetches Canadian province data from StatCan (ZIP/CSV)
   - Fetches US state data from EIA API
   - Sanitizes data (fills missing periods by extrapolating from parent regions)
   - Adjusts for energy imports (continent mix blended into country mix)
   - Exports energy mixes and impact factors at all granularities (world/continent/country/subdivision × monthly/yearly × global/green)

### Data Directory (`data/`)

| Directory    | Content                                                              |
|-------------|----------------------------------------------------------------------|
| `cloud/`    | Cloud provider regions, VMs, CPUs, accelerators (AWS, Azure, GCP, Scaleway) |
| `country/`  | Regions, countries, continents, distances                            |
| `energy/`   | Environmental impact per energy source (per kWh)                     |
| `equipment/`| Embodied impacts of ICT equipment manufacturing                      |
| `factor/`   | **Generated** — impact factors per kWh consumed, by region/period    |
| `mix/`      | **Generated** — energy mix ratios by region/period                   |

`factor/` and `mix/` are regenerated by `yarn build:data`. Other directories contain source/reference data.

### Site (`site/`)

React + Vite app for data visualization. Uses MUI for styling. Vite config sets `root: "site"` and `publicDir: "../data"`.

### CI/CD (`.github/workflows/main.yml`)

Runs daily (cron) + on-demand. On `main`: generates data, bumps version if changes detected, publishes to npm, deploys site to GitHub Pages.

Publishing goes through npm OIDC trusted publishing: the repository is the publisher, no personal npm account is involved.

For a documentation-only release, dispatch `main.yml` on `main` with `force_publish: true` and `refresh_data: false`. This validates and publishes the committed dataset snapshot without fetching upstream sources. Scheduled generation and normal manual runs refresh data by default.

## Key Data Concepts

- **Regions** are identified by ISO 3166-1 alpha-2 codes (countries) or `XX-YY` format (subdivisions, e.g. `US-CA`, `CA-QC`)
- **Impact types**: ADPe, AP, CTUe, CTUh-c, CTUh-nc, GWP, IR, PM, WU
- **Green energies**: Bioenergy, Hydro, Solar, Wind. Files suffixed `-green` contain green-only factors
- **Periods**: yearly (`"2023"`) or monthly (`"2023-01"`)

## Code Style

- TypeScript with `ts-node` (no separate build step for data generation)
- Indentation: 2 spaces, UTF-8, LF line endings (see `.editorconfig`)
- Formatter: Prettier

## Maintain the LLM documentation

The following files are static, version-controlled documentation maintained by contributors and agents. They are not generated from the datasets or website pages:

- `llms.txt`: short entry point for the installed npm package, with package-relative links.
- `llms-full.txt`: complete package usage reference, readable offline.
- `site/llms.txt`: short entry point for the public website, with absolute public URLs.
- `site/llms-full.txt`: complete website usage reference, with absolute public URLs.

Review and update the affected files whenever a change adds, removes or renames collections or files; changes schemas, identifiers, units, geography/period coverage rules, missing-value semantics, estimation or fallback rules; changes sources, attribution or licensing; or changes public documentation/download routes. Keep shared facts consistent across the package and website variants. Ordinary data refreshes that preserve the documented contract do not require a documentation edit. Avoid hard-coded release versions, record counts and date ranges that would become stale on each refresh.

Keep the short files concise and link to the full reference for detail. The full files document schemas, methodology, examples and limitations; do not concatenate raw datasets into them. Describe only files present in this checkout. The website currently has six editorial collections; geographic reference files are downloads, not geography collection pages.

`site/scripts/build.mjs` copies the website variants unchanged to `site/dist/`. Do not edit build output. Ensure the package variants remain in the `package.json` publish allowlist. Do not replace these files with a skill or assume agents load them automatically.

After changes, run `yarn build:site`, `yarn check:site` and `yarn test:site`. Check that package-relative links resolve in the packed npm artifact, public documentation/download links resolve in the built website, and both website files are exact copies of their source files. Do not run `yarn build:data` just to validate documentation: it fetches upstream sources and rewrites data.

## Historical territory coverage

The five territories absent from the current Ember export are retained from the immutable snapshot in `sources/ember-legacy-territories.json`. `scripts/electricity-history.ts` restores country-level mix/factor outputs after aggregation, exports matching CSV files and writes `data/electricity-provenance.json`. Do not feed these already modeled outputs back into energy aggregation or overwrite the pinned source with generated files. Retain unknown upstream observation dates as unknown; review `sources/README.md` before changing this policy.
